Artifact Overview

Original Project

The Mobile Inventory App was originally created in CS-360 Mobile Architecture and Programming. It is an Android application that uses SQLite to store inventory and user information.

The original application allowed users to log in, create inventory items, edit inventory, and receive SMS notifications when inventory became low. Because I built the application from the ground up, I already understood how the different parts worked together before beginning the capstone enhancement.

I selected this artifact for the Databases category because it gave me the opportunity to demonstrate database development while also showing a different side of my software development experience. My other artifacts focused on web applications, while this project let me include Android development and show that I can work across multiple platforms.

Enhancement

What I Improved

The biggest improvement I made was redesigning the database into a normalized relational structure. Instead of storing everything in a single inventory table, I separated manufacturers, categories, warehouse locations, users, inventory items, and transaction history into their own related tables.

This reduced duplicated data, improved organization, and made the application easier to maintain as it grows. I also added foreign key relationships so the different parts of the database could work together in a more structured way.

I expanded the application by adding inventory history, soft deletion with item restoration, warehouse location tracking, and automatic loading of a realistic inventory dataset from a bundled CSV file during the initial database setup. The application now starts with a populated warehouse instead of requiring every item to be entered manually.

Security was another major improvement. The original application stored passwords in plain text, so I replaced that approach with PBKDF2 password hashing and unique salts for each user account. I also added automatic password migration so existing accounts are upgraded after a successful login, while new accounts are stored securely from the beginning.

I also updated the login process so usernames are no longer case sensitive while passwords remain case sensitive. This improved the user experience without weakening account security.

Finally, I restored and improved the low inventory notification workflow after redesigning the inventory management screens. The application now records transaction history, updates the Warehouse Chat notification system, and attempts to send SMS alerts when an item transitions into a low inventory state.

Reflection

Working through this enhancement taught me much more about database design than simply creating tables and storing data. I learned how normalization improves data integrity, reduces duplication, and makes an application easier to expand in the future.

I also gained a better understanding of how changes to the database affect the rest of the application. Updating the schema required changes throughout the user interface and application logic, which reinforced how closely connected the database is to the rest of the application.

One of the biggest challenges was redesigning the database while keeping the application working correctly. As the database became more advanced, features such as inventory history, item restoration, user authentication, and notifications all had to work together with the new structure.

Another challenge was restoring the SMS notification system after redesigning the inventory screen. Moving the quantity adjustment process into a different activity required tracing where the original alert logic existed and integrating it into the new workflow without creating duplicate alerts.

This enhancement also gave me more experience improving an existing project instead of simply starting over. I built on the original application by improving its database design, security, and overall functionality while maintaining the existing user experience.

Overall, this artifact demonstrates how much my database knowledge has grown since completing the original project. The application now reflects a more realistic database design, stronger security practices, improved inventory management, and a more polished user experience while still building on the foundation of the original assignment.
