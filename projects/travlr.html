Artifact Overview

Original Project

Travlr Getaways was originally created in the CS-465 Full Stack Development course. The project is a full-stack travel application that allows customers to view available travel packages while providing an administrative side for managing trip information.

The application uses Angular for the administrative interface, Node.js and Express for the server and API, and MongoDB for storing trip and user data. The original project gave me experience working with both the front end and back end of an application and connecting the different parts into one working system.

Before beginning the capstone enhancement, I reviewed the original application and refamiliarized myself with how the API, database, authentication, and Angular administration features worked together. That review helped me identify areas where the application could be made more secure, reliable, and easier to use.

Enhancement

What I Improved

For the capstone enhancement, I focused on improving the security, reliability, and usability of the Travlr Getaways application. The original project already had the main full-stack structure in place, so the goal was to strengthen the parts of the application that would matter most in a more realistic production environment.

I improved the API by protecting administrative routes so that unauthenticated users could not access management functions. I also added stronger server-side validation for required trip fields and added checks to prevent duplicate trip codes from being saved to the database. These changes helped make the application more consistent and reduced the chance of invalid or conflicting data being stored.

I also improved error handling so the application could return clearer responses when something went wrong instead of failing without useful information. On the Angular side, I updated the administrative forms to better support validation and give the user clearer feedback when information was missing or invalid.

Together, these changes made the application more secure and easier to manage while keeping the original architecture and purpose of the project intact.

Reflection

Enhancement Narrative

Why I Selected This Artifact

I chose Travlr Getaways for my ePortfolio because it represents one of the most complete software engineering projects I completed during the Computer Science program. It combines front end development, server side development, database integration, RESTful APIs, and authentication within one application.

I also selected it because it demonstrates the type of software development work I would like to continue doing professionally. The original project met the course requirements, but there were several areas that could be improved, including validation, API responses, duplicate trip codes, and the overall consistency of the administrative interface.

Enhancement Process

The main goal of the enhancement was to improve the design, security, and usability of the application while applying stronger software engineering practices. I improved the authentication workflow, protected administrative routes, added stronger API validation, improved error handling, and prevented duplicate trip codes from being stored in MongoDB.

I also redesigned the Add Trip and Edit Trip forms to provide better validation and clearer feedback. Trip length was changed from a free text field into separate days and nights values that are combined automatically. I also updated the administration pages so they more closely matched the public website and corrected the way trip images are displayed when different image dimensions are used.

Reflection

Working on this enhancement showed me that improving an existing application requires a different approach than building something from the beginning. Before making changes, I had to spend time refamiliarizing myself with how the Angular front end, Express API, and MongoDB database worked together.

One of the biggest challenges was maintaining compatibility while improving the application. Changes to the API also required updates to the Angular components so they could correctly handle the new validation rules and responses. I also had to balance usability and security so that users received helpful feedback without allowing invalid or duplicate data to reach the database.

Overall, the enhancement made the application more polished and professional while strengthening my understanding of validation, error handling, authentication, user experience design, and data integrity. It also reinforced that quality software development is not only about making code work, but about continuing to improve the design, security, maintainability, and experience of the application.
