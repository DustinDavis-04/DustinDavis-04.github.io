Artifact Overview

Original Project

The Grazioso Salvare Animal Shelter Dashboard was originally created in CS-340 Client/Server Development. The original project used a MongoDB database with a Dash dashboard that allowed users to search and filter animal records from the Austin Animal Center dataset.

Users could choose different rescue mission types, view the matching animals in a table, and display the selected animal on a map. While the original project worked well for filtering data, most of the decisions were based on simple searches.

I selected this artifact because I saw an opportunity to expand it into something that actually analyzes the data instead of only displaying it. It also gave me the chance to demonstrate algorithm design and data processing rather than focusing only on the user interface.

Enhancement

What I Improved

For the capstone enhancement, I added a structured data preparation process that cleans and standardizes the intake and outcome datasets before the rest of the application processes them.

I then created a matching algorithm that connects intake records with the correct outcome records using the animal ID and record dates. Because some animals had multiple intake records, the algorithm had to determine which intake belonged with each outcome instead of simply matching the first record it found.

After the records were matched, I created a rescue suitability scoring system that evaluates each animal for different rescue missions based on breed, age, and sex. Those scores are used to rank the animals so the dashboard can show the strongest candidates first instead of simply listing every matching record.

I also reorganized the project so the data preparation, matching, scoring, and dashboard helper functions each have their own responsibilities. Additional helper functions handle tasks such as exporting data, selecting candidates, and working with missing location information. This made the project easier to read, test, maintain, and update.

Reflection

Enhancement Narrative

Why I Selected This Artifact

I chose the Grazioso Salvare Animal Shelter Dashboard for my ePortfolio because it gave me the opportunity to show how I can design and improve algorithms instead of only building a user interface. The original dashboard worked well for filtering animal records, but most of the decisions were still based on simple searches.

I saw an opportunity to expand the project into something that actually analyzes the data before presenting it to the user. That made it a strong fit for the Algorithms and Data Structures category and gave me a way to demonstrate data preparation, record matching, scoring, ranking, and more structured decision making.

Enhancement Process

I started by adding a data preparation process that cleans and standardizes the intake and outcome datasets before the rest of the application uses them. From there, I created an algorithm that matches intake records with the correct outcome records by using the animal ID and the dates the records were created.

Because some animals had multiple intake records, the matching process had to determine which records belonged with each outcome. After the records were matched, I built a rescue suitability scoring system that scores each animal for different rescue missions based on breed, age, and sex. Those scores are then used to rank the animals so the dashboard can show the strongest candidates first.

I also reorganized the project as it became more complex. The data preparation, matching, scoring, and dashboard helper functions were separated into their own modules so each part had a specific job. I added helper functions for tasks such as exporting data, selecting candidates, and handling missing location information. Breaking the project apart this way made the code easier to read, test, and maintain.

Reflection

The biggest thing I learned during this enhancement was how much planning goes into building a good algorithm. Writing the code was only one part of the process. I spent a lot of time thinking about how the data should move through each step so the final results would be accurate.

I also learned how much easier a larger project is to manage when the code is modular. As I added each enhancement, I tested the results before moving on to the next step. That helped me catch problems early instead of trying to troubleshoot everything at the end.

One challenge I ran into was getting the dashboard table to behave the way I wanted. I originally used Dash's active cell feature to determine which animal was selected, but it always left an unwanted highlighted cell. After trying several approaches, I switched to Dash's supported row selection instead. It added a radio button to the table, which was not exactly the appearance I originally wanted, but it solved the problem and made the code much cleaner.

That experience reinforced that the best solution is not always forcing the software to behave a certain way. Sometimes using the supported, reliable, and maintainable approach is the better design decision.

Overall, the project changed from a dashboard that mainly filtered information into one that prepares, analyzes, scores, ranks, and then presents the data. The enhancement gave me more experience designing algorithms, organizing larger projects, testing my work, and making decisions that improve both the code and the user experience.
